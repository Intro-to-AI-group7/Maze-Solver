Detailed Description

Core maze model storing occupancy, neighbor links, and start/goal nodes.

The maze uses a rectangular grid of Node objects. Traversable cells contain a Node reference and blocked cells are null. Neighbor links represent geometric adjacency between traversable cells, while each direction has a movement cost. Enabled movement costs are positive integers from MIN_MOVEMENT_COST through MAX_MOVEMENT_COST; zero is reserved for disabled or non-existent movement. Direction order is always [NORTH, EAST, SOUTH, WEST].

Example import format for importFromFile(String) is: row count, column count, start: row,col, end: row,col, then one layout row per maze row using 1 (path) and 0 (wall). An optional WEIGHTS section may follow the layout. It contains one comma-separated four-value row for every grid coordinate in row-major order. Values use [N,E,S,W] order; 0 means no permitted movement and positive integer values are movement costs. If the section is absent, adjacent traversable cells default to cost 1. Example: 



4

5

start: 3,0

end: 0,4

11111

10001

10101

11111

Typical implementation flow: 



Maze maze = Maze.importFromFile("test/resources/maps/test_346x346.msmap");

Maze.NeighborValidationResult vr = maze.validateNeighborConnections(25);

if (!vr.isValid()) {

    for (String issue : vr.getIssues()) {

        System.out.println(issue);

    }

}

maze.exportToFile("out.msmap");

inlinestatic

Builds a random, guaranteed-solvable maze with the given dimensions.

The generated maze keeps the outer border blocked and carves interior corridors using a depth-first backtracking strategy to produce a classic maze appearance. For even dimensions, a follow-up pass extends corridors into the final interior row/column so right/bottom edges are not left as persistent solid strips.

Parameters
lengthtotal number of rows (minimum 3)
widthtotal number of columns (minimum 3)
Returns
newly generated solvable maze
Exceptions
